Original prompt for Layout and Filmstrip concept :

State feasibility but do not implement this feature:
Consider a Document Zoom or Document Outline (slides) capability similar to pages outline in desktop apps like MS Word or OpenOffice Impress.
Purpose is to let user scope out of immediate text view to see the structure of the entire buffer (or reasonable subset that can be seen visually).
And also to select a page to bring into the editor view.
On a desktop this is easy because there is lots of screen space.
On a small device such as a phone this is a challenge. If the zoomed pages are too small it is not useful. A tablet it may be better.

In an DOSwriter zoom or slide function the user would need to set a font and page length. This differs from DOSwriter text font zoom concept.
Default page size would be 8.5x11 inches with 12-point font, portrait mode. User would have font size options 10,12,14,16,18.
User could change it to landscape and maybe some smaller page options, like 6x9, 5x8, 4x5, 3.5x2.

There would be 2 view modes.

1. Layout Mode : 8 images of the buffer in the default or user page size are shown on the device screen. If user presses LEFT/RIGHT arrow keys, the 8 image window slides to the previous or next text of buffer that fits into the 8 page screen view. The 8 pages are the sliding window to view the whole buffer. As the user slides the view, one of the pages (3 of 8) is highlighted. If user presses Enter, the Layout view closes and that section of the buffer is broought into focus in edit mode.

2. Filmstrip Mode : One page size page view is shown, LEFT/RIGHT arrows slide this view across the entire buffer. If user presses Enter, that section of the buffer is brought into focus in edit mode. If user presses Esc DOSwriter returns to edit mode where they launched Filmstrip Viewer from. If the user sets up the page and font size similar to their editing font size and margins, the Filmstrip view would be almost identical to their edit settings.

Of these two idea I think Filmstrip Mode might have most feasibility and utility. Review and comment on both modes.


Your response :

This is an excellent conceptual direction for DOSwriter. It bridges the gap between a distraction-free writer and a layout-aware manuscript manager.
Here is the feasibility analysis and a comparison of both modes from a technical and UX perspective:
1. Overall Feasibility: High
The underlying logic for this already exists in DOSwriter's recent updates. We have:
•
A Pagination Engine: Built for the PDF export (Ctrl-P), which knows how to measure text and break it into physical page chunks.
•
Bitmap Caching: Built for the PDF viewer, which allows for smooth "sliding" of pre-rendered images.
•
Coordinate Mapping: The ability to link a specific pixel/page coordinate back to a character index in the text buffer.
2. Layout Mode (Grid View)
Feasibility: Medium-High
•
The Challenge: On a mobile phone, 8 pages squeezed into one screen will be essentially illegible. However, as you noted, readability isn't the primary goal here—structure is.
•
The Utility: This is a "Structural Map." It would be highly useful for spotting:
◦
Chapter transitions (looking for the # headers).
◦
Paragraph density (spotting "walls of text" vs. light dialogue).
◦
The "Shape" of the manuscript.
•
Technical Constraint: Rendering 8 pages simultaneously is a heavy CPU task. To make this smooth, we would use "Thumbnail Rendering" (rendering at half-resolution) to save memory and increase speed.
3. Filmstrip Mode (Single Slide View)
Feasibility: Very High
•
The Utility: This is essentially a "Page-Flip Edit Mode." For many writers, scrolling vertically is exhausting. Flipping horizontally through discrete "pages" that look like a real book (6x9 or 8.5x11) provides a much better psychological sense of progress.
•
The Implementation:
◦
This is actually easier to implement than Layout Mode because we only render 3 pages at a time (Current, Previous, Next).
◦
If the user matches their edit font/margins to the Filmstrip settings, it becomes a "Print Preview" mode where they can still see the cursor and jump into text.
•
E-Ink Synergy: Filmstrip Mode is perfect for E-ink. It replaces the "ghosting" and "blurring" of vertical scrolling with clean, static page refreshes.
4. Technical Comparison
Feature
Layout Mode (8-up)
Filmstrip Mode (1-up)
Mobile Phone
Structural only (no legibility).
High legibility; acts as a reader.

High utility; looks like a storyboard.
Very comfortable reading mode.

Resource light (needs 3 bitmaps).

Best for close-range review.

5. My Recommendation
I agree with you: Filmstrip Mode has the most immediate utility for a writer.
It transforms the app into a "Live Paginator." Instead of just writing a long stream of text, the user can instantly see, "I have written 42 pages of a 6x9 novel."
Layout Mode acts more like a "Story Board" and would be the natural evolution of Filmstrip Mode once the pagination logic is perfected.
Conclusion on Feasibility:
Both are highly feasible without adding heavy external libraries. We would simply reuse the existing StaticLayout engine (used in Markdown/PDF export) to generate the "Slides" and store them in the pdfCache (renamed to a general renderCache).
This would officially move DOSwriter from being a "Text Editor" to a "Professional Authoring Environment."
